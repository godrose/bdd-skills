# Discovery: the README for a public repository, and what was checked before the flip

Input: the goldfish runs on the README (access was its top blocker), `README.md`, `install.sh`, `specs/features/skills-readme-private.feature`, and an audit of the tracked files, all history and the pull requests on 2026-11-13. The builder said the repo will go public and the names are final. Two questions were asked: the order of the change and the release, and which clean-ups to do.

## Story

When the repo is public, a newcomer installs the plugin and the project files with no access step, and finds nothing in the README, the tree or the pull requests that was meant to stay private.

## Existing behavior

- The README says the repo is "private for now" in Quick start, Before you start and a whole Access paragraph, and says the `curl` install works only once it is public.
- `skills-readme-private.feature` checks that text.
- Seven discovery packs and one trial record name a trial project, and one pack file carries its name.

## The audit (read-only, before any change)

| Check | Result |
|-------|--------|
| Secrets and tokens, tracked files (341) and all history (253 commits, every ref) | None. AWS, GitHub, Slack and OpenAI-style keys and private key blocks. |
| Emails in tracked files | Only an npm package author in a lockfile. |
| Personal paths in tracked files and in `main` history | None. A personal path sat in two commits of a branch that was not `main`. It stays in the pull request commits. |
| Session links | 4 commits on `main` and 11 more on other branches (trailers), and the descriptions of 3 pull requests. They point to private sessions that need a login, so the risk is low. |
| Author email | The builder's personal address is on 251 commits and becomes visible. |
| Trial project name | In 8 tracked files and one file name. |
| Branches | 54 remote branches, 53 with a merged pull request and 1 with a closed one. |

## Agreed examples

| # | Situation | What happens |
|---|-----------|--------------|
| E1 | A newcomer reads Quick start and Before you start | No access step. The plugin installs from the public marketplace with the commands shown. |
| E2 | A newcomer wants the project-file install | The `curl` line works and is shown. The clone form stays as the alternative. |
| E3 | The README text about private access | It is gone: Quick start, Before you start and the Access paragraph. |
| E4 | A maintainer adds a file that names a trial project | A test fails. |

## Decisions

| # | Decision | Reason |
|---|----------|--------|
| 1 | The go-public README change comes first, then the 0.7.1 release. Chosen by the builder. | The tag then marks a README that a newcomer can follow. |
| 2 | The three pull request descriptions lose the session link (done). Chosen by the builder. | Edits only, and reversible. |
| 3 | The 54 merged or closed remote branches are deleted (done). Their last commits are saved in a list so each can be restored. Chosen by the builder. | The public view is tidy, and the stale branch with a personal path is gone. Pull requests keep their commits. |
| 4 | The trial project's name is replaced by "the .NET project" in the 8 tracked files, and the dogfood pack file is renamed. Chosen by the builder. | The rule is to keep project names out of this repo. |
| 5 | History is not rewritten. | The session links, the path in the pull request commits and the author email are in shared history. A rewrite needs a force-push, which is denied, and it breaks every pull request link. The builder knows this and accepted the low risk. |
| 6 | The replaced private-access scenario file is deleted, and a new feature says the README no longer says it. A policy check fails when a tracked text file names the trial project. The name is built from parts in the step, so no file holds it. | The earlier decision of 2026-11-12 (the README says the repo is private) is reversed. |

## Existing users

README text only, plus renamed docs. No plugin file changes. Anyone linking to the old dogfood pack file gets a dead link.

## First run

A newcomer sees no access step and installs with the commands in Quick start. The `curl` install works once the repo is public.

## Exclusions

- The flip itself (repository visibility). The builder does it.
- Repository settings: branch protection, security features, topics and description.
- Rewriting history, and hiding the author email on old commits.
- The 0.7.1 release (next, as its own release PR).

## Order of the flip

Merge this PR, then change the visibility to public, or the other way round. Between the two the README either says nothing about access to a private repo (merged first) or still says it (flipped first). Merging first is closer to right.

## Not proven by this change

- That the `curl` install works from a public repo. It cannot be tried until the flip. It is the first thing to check after it.
